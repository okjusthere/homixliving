## 用户已确定的入口

| 场景 | Portal 入口 | 目标行为 |
| --- | --- | --- |
| 经纪人入职合同 | 登录后自动识别并恢复 `/pending` 当前入职步骤 | 资料确认后准备合同，本人继续签署和付款；不去通用工作台找模板，不重复建合同或发信 |
| 买家/卖家 package 与个性化文件 | 工作台固定“文件签署”入口，建议 `/signing` | 一处选包、预填、确认、发送、查看状态、继续原生编辑和下载 |
| 管理员入职处理 | `/admin/agents?view=onboarding` → 处理入职 | 资料、合同、收款、实际权限独立处理，按未完成事项跟进 |

Documenso 负责所有电子签署与原生编辑。Portal 管理业务身份、线下/历史合同核验、收款、正式开通及有限权限例外。电子签署事实不能由管理员例外或前端回跳参数伪造。

当前一两份 native 待签任务不迁移，也不需要双引擎兼容。“既有人员历史合同核验”作为日后需要的业务能力，仍必须建设；它与迁移 native 草稿不同。

## 文件签署工作台

- 工作台导航新增“文件签署”，包含买家包、卖家包、上传个性化文件三个入口。
- 统一列表：待我处理、草稿、待他人签署、已完成、异常/过期；按客户、房产、文件名搜索。
- 列表每行有文件/包名、业务关联、签署进度、更新时间和下一步。详情含原件、签署人、事件和完成文件。
- 包先选择公司发布的实际文件组合，资料填一次，预览收件人及文件清单后确认发送；不自行杜撰法律文件组合。
- 编辑使用 Documenso 原生界面，返回 Portal 时回到该任务并保留筛选条件；不能仅跳至上游首页。
- 经纪人只看自己的客户文档及明确授权文件。Documenso 原生权限必须同样成立；HR 文件不会因共享团队模板而被全员访问。
- 个人入职合同在入职/个人资料中查看，不混入客户包主操作。管理员包配置进入已有管理员系统。

## 管理员工作台交付

### 以实际事项组织待办

默认统计未完成事项对应的人，而不是只查 pending 账号。已开通但待公司会签、例外待补签、线下合同待核验、收款待匹配仍要出现。人员数与事项数分别标注，避免重复计人。

列表直接显示卡点、下一责任人和动作；详情有资料、合同、收款、权限四区及共用时间线。暂不处理/关闭本次入职需要原因并可恢复，不删除或抹掉实际合同、收款和授权记录。

### 四条办理路径

| 路径 | 管理动作 | 结果 |
| --- | --- | --- |
| 标准电子入职 | 继续/提醒签署、检查状态、核验实际收款、按条件审批 | 线上本人签署后 Stripe 付款自动开通；线下核验收款后管理员审批 |
| 纸质签署 | 上传已签文件、登记公司/用途/版本/日期/角色，核验或退回 | 标明“线下合同已核验”；满足对应要求，其他缺项继续待办 |
| 既有公司经纪人 | 核验历史合同、身份与适用条款、财务适用情况，专用开通 | 不重复新入职签约或自动收一次新入职费；不是伪造已签/已付款 |
| 未签，先用部分功能 | 理由、白名单能力、补签期限和责任人，授予有限权限 | 显示“例外开放 · 待补齐”；到期/撤销生效，实际合同和付款状态保持真实 |

纸质文件上传不等于核验通过。已核验文件替换必须新建版本再核验，核验可撤销并留痕。本人签完但公司未签仍保留会签待办。对不再使用的线上邀请安排明确取消动作及失败跟踪，避免继续重复催签。

### 先记录实际收款，再判断开通资格

本人未签、资料未全或团队条款未完成，不妨碍管理员登记真实收到的金额、方式、日期和凭据。项目/金额未确定时保留为“已收款 · 待匹配/核对”。

收款、匹配应付、套餐/奖励结算、账号开通分开处理。不得为了登记收到的钱就提前开通、开始套餐或重复产生奖励。复用现有账务规则，加入同一凭据、重复请求及线上/线下并发到款的防重。

### 例外权限是真正的有限权限

首期建议白名单为完善本人资料、培训学习、普通公司资源阅读，叠加原有资源可见权限；管理员逐项选择并设置截止时间。它不自动包含客户合同发送、财务或管理他人的能力。

例外作为独立授权记录，不将账号写成完整 active。统一计算 `effectiveAccess`；中间层、页面和 API 协同，不能一边允许培训、一边因非 active 被送回 `/pending`，也不能直接放开所有 API。

接口读取最新授权和服务端时间，因此旧 JWT 不能越过到期/撤销。后台只负责提醒与待办。完成正规入职后结束例外并取得完整权限，旧例外到期不能收回正规权限。

## 实施顺序

1. 与 eSign Phase 0 同步确定真实 Documenso 身份/编辑/回程，以及 Portal 多来源合同、收款、开通和例外权限的数据与判断模型。
2. 完成数据库和服务端能力，再接四区管理员界面；线下核验、收款、既有人员和有限权限是同轮明确交付，不留作泛泛后续优化。
3. 将登录自动入职换到 Documenso，回归线上自动开通和线下审批，验证已开通但待公司签署仍留待办。
4. 交付独立文件签署工作台及买家、卖家、个性化文件流程。
5. 三条 Documenso 流程和管理员特殊路径验收通过后，完成 native 代码与服务退役。

## 验收用例

- 登录/刷新/换设备回到同一入职任务；已核验线下合同不强制重新电子签署；已开通但待会签不重新进入新入职。
- 未签先收到线下款可登记；资料未定保留待匹配，不错误开通和结算；重复/并发收款不重复入账。
- 纸质合同上传、核验、退回、撤销和替换可追踪；线下核验不改写 Documenso 的电子签署事实。
- 历史合同核验后通过既有人员路径开通，收费适用可解释，不重复新入职费；缺项仍有待办。
- 例外只允许指定页面与 API；到期/撤销在旧会话中立即阻止，补齐后正规权限不受旧例外影响。
- 正常编辑、导入/创建、恢复账号、签署和付款回调都不能绕过专用开通/授权判断。
- 管理员可找到已开通但仍未办完的人，人数与事项数正确，暂缓可恢复。
- 文件签署工作台原生编辑返回同一任务；客户共同签署人与多文件字段正确，文档及 HR 权限不越界。
- 两个工作台在桌面和移动端可用；新增页面遵循现有双语约定。

以上为实施前规划。实际执行状态见下方实施记录及两仓库的验收报告。
