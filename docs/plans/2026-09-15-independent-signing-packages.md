# 公司独立文件与可配置签署包

更新：2026-09-15。当前实现与验收结果以本文为准；9 月 13 日方案保留为历史记录。

## 本轮交付

公司逐份维护 PDF、角色、字段和版本。管理员在签署管理中审核一份文件后，将已审核版本按顺序组合成文件包。文件包保存明确的版本引用，不复制一份需要重新维护的大 PDF。

经纪人选择公司文件包，填写一次客户、房产和协议资料，预览每份文件后发送。公司名称、地址、公司执照号、经纪人身份由 Portal 档案和公司设置带入。第二位客户按需添加；无需为不同人数、不同公司复制内容模板。经纪人和客户无需原生 Documenso 账号。

本轮买家目录：

| 独立文件 | 用法 |
|---|---|
| Exclusive Buyer Representation Agreement | 独家买家包中的代理协议 |
| Non-Exclusive Buyer Representation Agreement | 非独家买家包中的代理协议 |
| Agency Disclosure — Buyer Side | 两个买家包共用，普通买方代理关系 |
| Lead Paint Disclosure — Buyer Side | 两个买家包共用，收集本方签署；对方签字与支持材料另行取得 |
| Buyer Commission Agreement | 两个买家包共用，费用由经纪人填写并核对与代理协议一致 |
| Deal Sheet | Company File，经纪人填报并确认，没有虚构签字栏 |
| Commission Report | Company File，经纪人签署；Admin Use Only 和公司付款审批不由客户或经纪人代签 |

独家、非独家买家包各引用四份文件；各文件也可单独办理补签。Company File 与买家包完全分开，接口禁止在 Company File 配置客户参与人。当前 Deal Sheet 自动带入本方资料的位置为 Selling Broker（买方经纪人填报）。

## 签署与归档

Bridge 在发起时把各文件编译进同一个原生 envelope，但每份 PDF 保持独立。相同业务角色按编号合并，同一经纪人在某份文件是确认人、另一份是签署人时，只建立一个签署身份。客户收到自己的统一入口，可以逐份阅读签署。角色顺序在组合包中由管理员明确选择。

完成件仍是各自的原生 PDF，包含原生完成证明；ZIP 另含审计、完成证明和 SHA-256 清单。清单记录公司、经纪人、业务参考、文件包版本和独立文件版本。Portal 显示逐份字段进度，只有整个原生任务完成封存后才显示完成件可下载，不能把部分字段填写等同于独立 PDF 已封存。

新版本不会改变已创建任务。停用单份文件版本会阻止引用它的新建及尚未发送的草稿；已发送任务继续签署，历史完成件仍能下载。原有入职和旧版文件包保持兼容。

## 验证

- 本机真实 Documenso 2.18：独家包、Homix Living、两位买家和经纪人完成；四份 PDF 独立下载，ZIP 包含四份完成件及证明/审计。
- 本机真实 Documenso 2.18：非独家包、Homix Realty、一位买家和经纪人完成；第二位客户未生成字段或任务。
- 原版 PDF 上加测试水印后签署，已检查代理协议、Agency、Lead、佣金协议签名页面。
- Company File：Deal Sheet 的 APPROVER 确认与 Commission Report 的经纪人签署均完成；管理员栏保持空白。
- Portal HTTP：两家公司权威资料覆盖伪造身份、公司越权被拒、四文件单任务结构通过；内部文件加入客户被拒。
- Bridge 单元/契约测试覆盖组合字段定位、身份冲突、公司隔离、审核与版本引用校验；既有权限和入职测试保留。

## 后续：录单交材料

下一步按交易关联已完成客户签署件和 Company File，选择原件提交公司审核。审核通过后可导出原件 ZIP，并生成单独标明用途的合并阅读副本。合并副本不覆盖原始签署 PDF。当前已保留归属、房产、参考号、版本和原件清单；尚未连接录单附件选择和公司审核流程。

个性化 PDF 编辑仍为第二阶段。本轮不创建经纪人的原生账号或 SSO，不开放个人原生编辑器。
