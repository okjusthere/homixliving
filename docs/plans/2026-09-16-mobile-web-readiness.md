# Homix 移动准备：保留现有登录和收款

当前决定：只服务 Homix 经纪人和内部人员；先做好手机 Web，不启动 App Store 交付。Google 登录与 Stripe 业务收费保持现状。

## 本轮已经推进

| 能力 | 本轮状态 |
| --- | --- |
| 人员停用／撤权 | 统一服务端权限判断，旧会话与重新登录不能恢复停用账号 |
| 数据最小返回 | 租售参与者接口限制字段；未发布培训回归验证 |
| 弱网重试安全 | 文件登记幂等，Stripe 未完成事件可重投，发送结果不确定时先核实 |
| 财务记录保护 | 保留已使用发票，付款与邮件发送并发不会覆盖收款 |
| 错误恢复 | 发票加载重试、发送人工核实、全局页面错误与断网提示 |
| 主屏入口基础 | 现有 manifest／图标继续使用，补安装元信息；不增加敏感数据离线缓存 |
| 持续验证 | 新的真实数据库回归接入 CI |

## 下一阶段可以直接实施的工程

1. **上传体验：** 进度、取消、明确重试。区分文件已传完但登记失败；重试登记复用同一 objectKey，不重复上传大文件。
2. **长表单恢复：** 明确哪些字段可暂存、什么时候清除。客户身份、银行资料、合同原文不能未经设计就统统放到 localStorage；优先服务端草稿和退出清理。
3. **真实设备验收：** iPhone Safari、添加到主屏、键盘遮挡、刘海／底部区域、文件选取、拍照 HEIC、PDF、签约、后台恢复、断网再连和账号过期。准备可删除的合成交易，避免在生产客户单上试操作。
4. **异常运营：** 为待确认邮件、Stripe 重试失败、外部账号开通待核实、孤立文件建立可查询队列与负责人；演练恢复和备份还原。日志不记录完整客户资料或凭据。
5. **可访问性与手机界面：** 系统字体放大、屏幕阅读器、触控尺寸、焦点顺序、横屏、较慢网络；对实际使用频率最高的租赁录入、资料上传和发票优先验收。

这些尚未全部完成；本次没有承诺可离线处理业务或已经达到原生 App 的后台能力。

## 需要 Homix 明确事实后才能上线的内容

| 事项 | 需要确定什么 | 为什么不能自动编造 |
| --- | --- | --- |
| 隐私说明 | 收集哪些资料、用途、供应商、联系人、保存期限和适用地区 | 说明必须与实际运营一致，不能用生成模板代替事实 |
| 账号删除请求 | 谁审核、如何确认身份、时限、保留哪些财务／合同资料 | 停用、删除登录身份、删除业务账本不是同一个操作 |
| 取消交易结算 | 有收款但取消的交易是否允许佣金结算，以及更正流程 | 当前行为可能是有意保留真实收入，不能简单一刀切禁用 |
| 管理员授权 | 哪些实际 Google 登录邮箱应在 `ADMIN_EMAILS` | 本轮按实际登录邮箱授权，账号的其他别名不继承管理权限；用户已确认四个地址 |

## 以后重新启动原生 App 时

再决定分发范围、组织开发者账号和客户端技术。届时需要系统认证会话／原生 Google 登录、App 回调与会话交换、真机及 TestFlight、隐私和账号删除流程、审核资料与应用包。支付和登录政策按当时真实功能与适用地区重新核实，不能把本文件当作 Apple 的审核许可。

本轮不制作 App 外壳，不增加 Apple 登录或内购，不把 Google 网页授权嵌入 WebView。已有后端权限和恢复能力可以被未来客户端继续复用。
